Design System

The build kit.

Tokens, components, modules, patterns. Every primitive an internal team or an outside partner needs to ship a When experience that feels consistent across products and domains.

00, System

Layout.

4dp baseline grid, three density modes, responsive column sizes scaled for content reading width (max 64ch for body text). Every spacing value lives on the grid; every breakpoint is named.

Breakpoints

smartphone
Compact · <600dp
Phone portrait. Single column. Drawer-style nav. Section-tabs collapses to icons.
tablet
Medium · 600 – 1023dp
Tablet portrait, foldable. Two column. Nav rail visible, side-sheet modal.
laptop
Expanded · 1024 – 1599dp
Tablet landscape, laptop. Three column. Nav rail + content + right-pane.
desktop_windows
Large · 1600dp+
Desktop. Full chrome. Content centered with viewport gutters.

Density modes

Three density tiers tune internal spacing without changing visual hierarchy. Set data-density="tight|normal|loose" on the <html> element. Every semantic spacing token flexes; the 4dp grid is preserved in every mode.

01, System

Tokens.

Three-tier architecture: md.ref is the static reference (palettes, raw spacing, typeface families). md.sys is theme-aware mapping (color roles, shape ladder, motion). md.comp is per-component aliasing. Component CSS only consumes --md-comp-*.

md.ref · reference

Palettes, raw spacing scale, typeface families, base shape values. No theming, no context. --md-ref-palette-primary-40, --md-ref-spacing-4.

md.sys · system

Theme-aware mappings, color roles (primary, on-primary), shape corner ladder, elevation, motion. Dark theme overrides md.sys only. --md-sys-color-primary.

md.comp · component

Per-component aliases that resolve to sys + ref. Component CSS reads only these. --md-comp-button-container-color.

Components · 01 Press me

Buttons

Five styles, four sizes. Press signature: transform scale(0.96) + border-radius corner-full → corner-large-increased on emphasized curve over 150ms. Filled lifts to elevation 1 on hover. Disabled is 38% content / 12% container per MD3 spec.

Styles

Filled · primary action

background: primary · color: on-primary
hover: elevation 0 → 1, state-layer @ 8%
press: scale 0.96 · corner-full → md · 150ms emphasized

Tonal · second action

background: secondary-container
Same press signature as filled. Pairs with one filled, never two filled side by side.

Outlined · alternative

1dp outline · color: primary · state-layer paints over outline at primary @ 8%/10%

Text · low emphasis

No background, no border, no lift, no shape-morph.
State-layer paints around the label only.

Elevated · ambient

surface-container-low + level-1 shadow
Hover: level-1 → level-2

Disabled · all styles

Container: 12% on-surface · Content: 38% on-surface · pointer-events: none

Sizes

XS → XL · same style, four heights

Type scales with container: label-large → label-large → label-large → title-medium → title-large
Press scale value is 0.96 across all sizes; shape-morph target is corner-large-increased (20dp) across all, the rounded family never breaks into a hard corner.

Components · 03 Press me

Floating Action Button

One per surface, reserved for the highest-priority action. 56dp standard, 96dp hero. Press uses spring · fast-spatial (the more aggressive overshoot, a real spring on the FAB feels delightful, not jittery, because the size carries it).

Resting elevation 3 · hover elevation 4. Press: scale 0.96 · corner morphs to extra-extra-large (48dp).

Components · 06 Hover

Cards

Filled cards: surface-container-lowest + elevation 1, rest. Outlined cards: surface + outline-variant border, no elevation. Both: corner-large (16dp). Interactive cards lift on hover (level 1 → 3 + translateY -2px).

Filled card · interactive

Outlined card · interactive

Components · 07 Resize window

Tab strip

Pills that become circles. At wide widths each tab is a label-pill auto-sized to its content. Below 600dp container width, the strip transitions to icon-only circles on spring · spatial, pills collapse to perfect circles (W = H = 64dp), bar shrinks to N × 64dp, sibling buttons touch.

Header, avatar (tertiary disc) · name · status indicator (green dot) · close icon button

Log, system bubbles are centered + faint, assistant bubbles are surface-container-high + bottom-left rounded sharp, user bubbles are primary + bottom-right sharp.

Typing, three dots, staggered animation, in an assistant-shaped bubble. Appears + disappears around assistant turn.

Suggested replies, chip row above the composer. One tap fills the composer or sends directly.

Composer, text field + circular send button. Send button shape-morphs to corner-large-increased on press.

Voice rule, Jamie says "I" not "we". Asks one thing at a time. Always offers a way to skip the chat and use the form.

Accessibility.

The When design system commits to WCAG 2.1 AA across every component and pattern. The rules below are baseline; specific components carry additional considerations called out in their anatomy.

Color contrast

Every text-on-surface pairing in the system has been measured. Body text clears 4.5:1 minimum, large text + UI elements clear 3:1 minimum. Full pairing table on Visual · Color.

Keyboard navigation

Every interactive element is reachable + operable with the keyboard alone. Tab order follows reading order. Focus is always visible.

keyboard_tab
Tab / Shift+Tab
Move forward/backward through interactive elements
keyboard_return
Enter / Space
Activate buttons, toggle chips, submit forms
close
Escape
Close dialogs, sheets, drawers, menus, the right-pane chat
arrow_drop_down
Arrow keys
Navigate within radio groups, menu items, tab strips

Focus indicators

Every interactive element has a 3dp primary outline at focus-visible, offset 2dp. Outlines are never less than 3:1 contrast with the surface behind them.

Reduced motion

A universal @media (prefers-reduced-motion: reduce) rule collapses every transition to 10ms and disables animation iteration. The site stays fully functional without motion.

Touch targets

Every interactive element clears WCAG 2.5.5 minimum (24×24dp visible target, 24dp hit area). Most components ship at 40dp+. Chip remove icons use a 20dp visual with 24dp hit area.

Screen reader semantics

Buttons are real <button> elements. Form fields have explicit <label> associations. Decorative icons are aria-hidden; functional icons have aria-label. Live regions for dynamic content (Jamie chat replies, snackbar messages) announce changes.

Color-blind safe pairings

Color never carries information alone. Error states pair color with an icon + helper text. Selected states pair color with a leading check. The full palette has been spot-checked against deuteranopia, protanopia, and tritanopia simulators.
